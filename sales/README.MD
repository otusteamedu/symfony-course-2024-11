Sales
===
Модуль Sales ограничивает контекст доменной области поддоменом Sales.
- Реализуем подписочную модель SaaS.
- Реализовано только ядро (`Application Core`)
- Ядро покрыто юнит-тестами
  - Тесты по большей части сгенерированы AI, их не следует воспринимать как образец хороших тестов.
  - Однако суть в том, что мы разрабатываем начиная с тестов и покрываем каждую модель, каждый юз-кейс тестами перед или во время разработки
- В рамках примера мы не реализуем реализацию Doctrine - суть Model-Driven Development в том, что начинаем разработку с ядра, инфраструктурой занимаемся потом.
- Вместо реальных инфраструктурных зависимостей в контейнере `config/services.yaml` мы подключили тестовые `InMemory`-реализации репозиториев, что позволяет и контроллеры сразу реализовать.

## Язык
- `Customer` - клиент (соответствует User из основного монолита)

- `Product` - продукт или тарифный план, на который подписываемся

- `Subscription` - подписка.
  Действия с ней и возникающие события:
  - `Create`   -> `SubscriptionCreated`
  - `Activate` -> `SubscriptionActivated`
  - `Cancel`   -> `SubscriptionCanceled`
  - `Renew`    -> `SubscriptionRenewed`

- `Invoice` - счет на оплату. Подписка каждый следующий период генерирует счет на оплату
  Действия с ним и возникающие события:
  - `Create` -> `InvoiceCreated`
  - `Pay`    -> `InvoicePaid`
  - `Expire` -> `InvoiceExpired`

`PaymentGateway` - платежный шлюз

## Сценарии использования
### Подписка
- Пользователь подписывается на продукт
- Создается подписка в статусе `pending`
- Пользователю возвращается идентификатор новой подписки
- По событию `SubsriptionCreated` создается счет на оплату

### Получение ссылки на оплату
- Пользовательский UI по идентификатору подписки поллит бэкэнд для получения ссылки на оплату
- Когда инвойс будет создан, бэкэнд вернет ссылку на оплату

### Оплата и активация подписки
- Пользователь переходит по ссылке и оплачивает счет
- Платежный счет вызывает HTTP вебхук при успешной оплате. Действие `Invoice.Pay`
- По событию `InvoicePaid` подписка переводится в статус `active`. Действие `Subscription.Activate`
